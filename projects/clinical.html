Clinical Intake Agent

A patient form goes in. Validated fields, a clinician note and a health-record export come out, and anything uncertain goes to a person. Here's one synthetic form going through it.

90.6%extraction accuracy, Llama 3.1 8B
0%hallucinated extracted fields
80 / 10CI fails below 80% accuracy or above 10% hallucination
6pipeline steps, each checkable on its own

How it's built

A FastAPI endpoint stores the upload and hands the job to a Celery worker through Redis, so the request returns instantly. The worker runs the six steps and saves results to PostgreSQL. A React review screen checks back every few seconds and shows flagged fields for editing. One setting switches the model between Claude, a local Llama 3.1 8B and a free mock for testing.

Python · FastAPI · Celery · Redis · PostgreSQL · React · Claude API · Llama 3.1 8B (Ollama) · Docker · GitHub Actions

What it doesn't do yet

Redaction is pattern-based plus one model pass, not a certified de-identification tool. The export is a subset of FHIR without medical codes. There's no login yet, and the test set is four typed, synthetic forms. The next step is grading summaries claim by claim against the extracted fields.

Synthetic data only. No real patient information is shown or used.
